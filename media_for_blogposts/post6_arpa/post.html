I put a website on .arpa — the top-level domain reserved for critical internet infrastructure. Not a subdomain of something on .arpa. A real address in the zone, resolving over real DNS, serving a real page.

That part was easy. What follows is everything that went wrong afterwards, because the interesting failures were not in the DNS.

The zone nobody registers

You cannot buy mysite.arpa. There is no registrar. The zone exists for machines: in-addr.arpa and ip6.arpa hold reverse DNS, the mapping that turns an IP address back into a name.

Reverse DNS is delegated. If you control an IP block, you control the corresponding slice of ip6.arpa. That is the whole trick — the specification says which addresses map where, and says nothing at all about what records you are allowed to put there.

So: get an IPv6 block, and its reverse zone is a domain you own.

Hurricane Electric hands out /64 prefixes for free. Their form asks for an IPv4 endpoint to tunnel from, and validates exactly one thing about it: that it answers a ping. Not that it is yours.

Mine came back 2001:470:1f15:4f4::/64. Turning that into a hostname is mechanical — pad each group to four characters, split into single characters, reverse:

2001:470:1f15:4f4
2001:0470:1f15:04f4
2.0.0.1.0.4.7.0.1.f.1.5.0.4.f.4
4.f.4.0.5.1.f.1.0.7.4.0.1.0.0.2.ip6.arpa

Cloudflare refuses to host that zone. deSEC does not. Point Hurricane Electric's reverse delegation at deSEC's nameservers, add a CNAME, deploy static files behind it, done.

Total cost: nothing. Total time: about twenty minutes.

Then I decided the page should be a fake CERN terminal with an ASCII wordmark, and lost an afternoon.

Every font lies about itself

The page renders its logo as ASCII art — slashes, colons, pipes, arranged so that each line has the same character count. It only works if every glyph occupies exactly the same horizontal space. Monospace is load-bearing.

I wanted a Japanese font for atmosphere, so I tried MS UI Gothic. It looks perfect and it is completely unusable, because it is proportional. Its ASCII advance widths, in font units, are thirteen distinct values — even the two slashes disagree. Feed the logo through it and the eleven lines — identical character counts — render between 15.54 and 20.88 em wide. A 34% spread. The letters stop being letters.

[[figure:ms-ui-gothic-widths]]

Fine. IPAGothic, then: same aesthetic, published free by Japan's IT Promotion Agency specifically as an MS Gothic stand-in, and genuinely monospaced.

That is when the yen signs appeared.

Twenty-three points where four would do

Japanese fonts have a habit older than Unicode. In JIS encoding, the byte at 0x5C was the yen sign. ASCII put a backslash there. Fonts that had to serve both drew the yen and moved on, and the convention never fully died — so U+005C in IPAGothic is not a backslash.

You can see it in the outline. The plain slash is four points, one diagonal stroke. The backslash at the same codepoint has twenty-three points, with horizontal segments cutting across it — two crossbars and a stem. That is not a slash with a quirk. That is a different letter wearing its address.

[[figure:glyph-outline-slash-vs-yen]]

So I removed \ from the subset, expecting the browser to fall back to Menlo for that one character.

The advance width you forgot to check

That fixed the yen signs and broke the art.

A font stack is per-character, not per-element. Drop one glyph from the embedded font and the browser sources that glyph only from the next font that has it — along with its metrics. Menlo at 14px advances 8.43px per character. The embedded subset advances 7px.

Every backslash in the logo became 1.43px wider than its neighbours. Eleven lines, ten different widths.

The fix was not to route around the glyph but to replace it. Take the slash outline, mirror it inside its own advance width, write it back over the yen glyph, keep the advance untouched:
pts = [(880,1683), (962,1647), (141,-129), (59,-92)]
mirrored = [(advance - x, y) for x, y in pts]

Twenty-three points back down to four. Grid intact.

The character that is not a character

While measuring that, a second alignment bug surfaced with the same signature and a stupider cause.

I had generated the glyph list with a filter that dropped whitespace — it read as obviously correct, the way wrong things do. The ASCII art is roughly half spaces. Every one of them was falling back to another font at another advance.

One line of the subset spec, {' '}, and 74 glyphs instead of 73.

Two bugs, one symptom, both invisible unless you measure. Which is the actual lesson here: after any font change, measure advance width per character across the logo's lines. Every line must report the same number. Eyeballing a screenshot at 14px will not show you a 1.43px drift, and it will absolutely not show you which of the two causes you are looking at.

getComputedStyle will not tell you

At one point the page was clearly not rendering the font I thought it was, and my check said otherwise. The check was worthless:

getComputedStyle(document.body).fontFamily  // "Gothic Terminal", …

That returns the declared stack. It is the CSS you wrote, echoed back. It says nothing about which face the browser actually resolved, or whether it resolved anything at all.

To find out, stop asking and start measuring. Draw the same string to a canvas in each candidate font, count opaque pixels, record the width:

[[figure:font-ink-fingerprint]]

The fastest single tell, though, came from a human. The zero. Monaspace draws it dotted; Menlo slashes it. One glance at a screenshot settled a question three programmatic checks had muddled.

Inline the font, not the request

The subset is 73 to 74 glyphs, which is small enough that the delivery question inverts.

deliverytotal sizerequestsrisk
separate .woff27,045 B2possible FOUT
inlined base647,490 B1no FOUT

445 bytes to remove a round trip and the flash of fallback text. The site is HTTP/1.1 — no HTTPS on .arpa, and browsers only speak HTTP/2 over TLS, so there is no multiplexing to soften a second request. A round trip costs tens of milliseconds. 445 bytes costs about four.

Inline wins, and the page stays one file with nothing external.

One licensing detail worth knowing before you do this: SIL OFL and the IPA license both treat a subset as a derived font, and both reserve the original name. Your @font-face cannot be called IPAGothic. Mine is Gothic Terminal, with the copyright notice kept in a comment above the rule.

Two bugs that had nothing to do with fonts

Centred content can be unreachable

I had this, and it looks reasonable:

html, body { height: 100%; overflow: hidden; }
body { display: grid; place-content: center; }

Centred content distribution overflows in both directions. On a window shorter than the content, the top of the page sits at a negative offset — and overflow: hidden means you cannot scroll back to it. Measured at a 693px viewport: top: -15px. The wordmark was simply gone.

Auto margins do not do this. They resolve to zero when the free space runs out, so a short window degrades into an ordinary scrolling page:

body { display: flex; }
.terminal { margin: auto; }

One timer handle cannot hold two timers

The D-Mail button plays a sequence: sending, then a status line, then an error. I wrote it like this:

let timer;
const queue = (text, delay) => {
  clearTimeout(timer);                    // ← kills the previous stage
  timer = setTimeout(() => { … }, delay);
};

queue(status, 1400);
queue(error, 4600);

The second call cancels the first before it ever fires. The status line — the whole point of the sequence — never appeared. It needed two independent handles, cleared together only at the start of a new click.

Both bugs shipped and sat there working-ish, which is the category I find most interesting: not crashes, just quietly wrong.

Adding a clock made me delete a whole section

Steins;Gate has a “Divergence Meter” — a nixie-tube readout of the worldline's drift, always slightly wrong. I wanted one on the page, live, no images.

The tubes are <span>s: a repeating-linear-gradient for the glass ribbing, a radial-gradient for the glow, text-shadow for the actual light, all in the palette already on the page. Seven of them, updated once a second, the last digit deliberately randomised — the joke is that a stable reading would be the anomaly.

[[figure:divergence-meter]]

Placing it was the actual problem. My first pass added it as its own section, full-width, between the masthead and the status grid. That pushed everything below it down by one section's worth of height, which on a page whose whole premise is “no scroll, fits in one screen” is a regression disguised as a feature. The fix wasn't tuning margins — it was noticing the D-Mail relay section had an empty second column doing nothing, and putting the clock there instead. Same row, zero added height, better use of the grid that already existed.

Then I made the actual damage report structurally pointless. It existed to hold three numbers: D-Mails sent, timelines ruined, bananas gelatinized. Once the joke stats got cut, it was a whole section — heading, <dl>, grid slot — built to display one line. I moved that line into the event log instead, as its own row, because that is what it already was: an event, timestamped, in a log full of events. Deleting a section to save one <dt>/<dd> pair felt wrong until I noticed the section was the only thing making it feel like more than one pair.

The layout shift was a reserved height, not a bug

The event log's new row reports a real send count and, I decided, should report a real time too — not a scripted 23:41:09, but the actual moment you clicked the button. Two clocks now run independently: the nixie meter ticks once a second and lies on purpose; the log row stamps once per click and does not lie at all. They share no state, deliberately — a decorative clock and an honest timestamp are different features that happen to look similar, and merging them would have made the honest one drift too.

That honesty produced a visible bug. The 403 error line is two sentences; the in-universe status lines are one. Both share a fixed-height container so the page doesn't reflow between them, but I'd sized that container for the common case, one line, then discovered the two-line error via clicking the button during review rather than by reading the CSS. Whatever renders last decides the box's height unless you reserve it up front — and “up front” means sized for the longest string that can ever land there, not the one you tested with first.

What it adds up to now

The site is one index.html, ~51 KB raw, ~30 KB gzipped, one request, no external calls. The event log holds two scripted lines of backstory and one live one; the D-Mail counter and its timestamp both update on click without touching the page's height. The Divergence Meter runs beside it, ticking on its own clock, agreeing with real time on purpose about six digits out of seven.

Clicking the wordmark runs the whole page through feTurbulence into feDisplacementMap — one static filter, one CSS class, no animation. A footer button swaps every visible string, and every aria-label, into Japanese. “Send D-Mail” plays its three-stage sequence and increments a counter in localStorage, which is as close to a backend as a joke page should get.

The DNS was a party trick. The typography was the work.
