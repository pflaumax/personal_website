I put a website on .arpa, the top level domain reserved for critical internet infrastructure. Not a subdomain. A real address in the zone, resolving through DNS and serving a real page.

See it live: cern.4.f.4.0.5.1.f.1.0.7.4.0.1.0.0.2.ip6.arpa

The DNS part took twenty minutes. Everything after that took much longer. None of the hard parts were DNS.

The zone nobody registers

You cannot buy mysite.arpa. There is no registrar for it. The zone exists for machines. in-addr.arpa and ip6.arpa handle reverse DNS, mapping an IP address back to a name. Reverse DNS is delegated. Control an IP block and you control its matching slice of ip6.arpa.

That is the trick. The specification defines which addresses map to which names. It says nothing about the records you can put there. Get an IPv6 block, and its reverse zone becomes a domain you control.

Hurricane Electric hands out /64 prefixes for free. Its form asks for an IPv4 endpoint for the tunnel and checks one thing: does it answer a ping? It does not check whether the address belongs to you.

Mine came back 2001:470:1f15:4f4::/64. Turning that into a hostname is mechanical:

2001:470:1f15:4f4
2001:0470:1f15:04f4
2.0.0.1.0.4.7.0.1.f.1.5.0.4.f.4
4.f.4.0.5.1.f.1.0.7.4.0.1.0.0.2.ip6.arpa

Cloudflare would not host the zone. deSEC would. I pointed Hurricane Electric's reverse delegation at deSEC's nameservers, added a CNAME record, and deployed a static page behind it.

Then I decided the page should be a fake CERN terminal with an ASCII wordmark, and lost an afternoon.

Every font lies about itself

The logo is ASCII art. Slashes, colons, and pipes arranged into lines with the same number of characters. It only works when every glyph has the same width. Monospace is not a preference here.

I wanted a Japanese font for the atmosphere, so I tried MS UI Gothic. It looked right. It was unusable. MS UI Gothic is proportional. Its ASCII characters have thirteen different advance widths. Even / and \ differ.

Put the logo through it and eleven lines with identical character counts render from 15.54em to 20.88em wide. A 34% spread. The letters stop being letters.

[[figure:ms-ui-gothic-widths]]

Fine. IPAGothic, then. It has the same aesthetic, was published by Japan's IT Promotion Agency as an MS Gothic replacement, and is monospaced.

Twenty-three points where four would do

Japanese fonts carry an old encoding habit. In JIS, byte 0x5C meant the yen sign. ASCII put a backslash in that slot. Fonts built to support both often drew a yen sign there, and the convention never fully disappeared. In IPAGothic, U+005C is not a backslash.

You can see it in the outline. The forward slash uses four points. One diagonal stroke. The character at U+005C uses twenty three points, with horizontal segments across it. Two crossbars and a stem.

That is not a backslash with a quirk. It is a different letter using its address.

[[figure:glyph-outline-slash-vs-yen]]

So I removed \ from the subset, expecting the browser to fall back to Menlo for that one character.

The advance width you forgot to check

A font stack works one character at a time, not one element at a time. Remove a glyph from the embedded font and the browser takes that character from the next available font. It takes that font’s metrics too.

Menlo at 14px advances 8.43px per character. My embedded subset advanced 7px. Every backslash in the logo became 1.43px wider than its neighbours. Eleven lines, ten different widths.

The fix was not to route around the glyph but to replace it. Take the slash outline, mirror it inside its own advance width, write it back over the yen glyph, keep the advance untouched.

Twenty-three points back down to four. Grid intact.

The character that is not a character

While measuring that, I found another alignment bug with the same symptom and a much dumber cause. I generated the glyph list with a filter that removed whitespace. It looked obviously correct. That is how wrong things usually look.

One line of the subset spec, {' '}, and 74 glyphs instead of 73. The logo is roughly half spaces. Every one of them had been falling back to another font with a different advance width.

Two bugs, one symptom, both invisible unless you measure. Which is the actual lesson here: after any font change, measure advance width per character across the logo's lines. Every line must report the same number. Eyeballing a screenshot at 14px will not show you a 1.43px drift, and it will absolutely not show you which of the two causes you are looking at.

Adding a clock made me delete a whole section

Steins;Gate has a 'Divergence Meter', a nixie tube readout of the worldline's drift, always slightly wrong. I wanted one on the page, live, no images.

The tubes are <span>s: a repeating-linear-gradient for the glass ribbing, a radial-gradient for the glow, text-shadow for the actual light, all in the palette already on the page. Seven of them, updated once a second, the last digit deliberately randomised, the joke is that a stable reading would be the anomaly.

[[figure:divergence-meter]]

Placing it was the real problem. My first version gave the clock its own full width section between the masthead and the status grid. It looked fine, but pushed the whole page down. A site meant to fit on one screen had gained a scroll bar.

The D-Mail relay already had an empty second column, so I put the clock there instead. Same row with no extra height. The damage report had the same problem. After cutting the joke stats, it was an entire section built around one live line.

I moved that line into the event log and deleted the section.

What it adds up to now

The site is one index.html, ~30 KB gzipped, one request, no external calls. The event log holds two scripted lines of backstory and one live one; the D-Mail counter and its timestamp both update on click without touching the page's height. The Divergence Meter runs beside it, ticking on its own clock.

Clicking the wordmark runs the page through a glitch effect built with feTurbulence and feDisplacementMap. One static filter, one CSS class, no animation.

I wrote more about browser glitch effects and the strange visual things you can build with native CSS and SVG filters here: Noise and Displacement.

A footer button switches every visible string and every aria-label to Japanese. Send D-Mail runs its three step sequence and increments a counter in localStorage, which is as close to a backend as a joke page needs.

The full source is on GitHub. It is one HTML file. Read it, break it, or send a pull request.

The DNS was a party trick. The typography was the work.
